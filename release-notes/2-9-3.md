### Decks 2.9.3 — DecksMD for iPhone and iPad, and a deck can no longer be emptied by a bad parse

Decks is now on the App Store as **DecksMD**, and this release fixes a way a deck could lose its cards.

#### **DecksMD on iPhone and iPad**

[DecksMD](https://apps.apple.com/app/id6801156953) opens the same vault this plugin does — the same markdown files, the same `#decks` tags, the same FSRS scheduling. It is not a sync service and keeps no copy of your notes: it reads and writes the files themselves, from a folder you choose or one it keeps in the Files app.

Review, cram, browse and exam are all there, along with the card editor, quick capture, PDF import and the Anki importer.

The app is free. A Decks Pro subscription works across both — one account, whichever you bought it on — and everything that is free in the plugin is free in the app.

#### **A deck can no longer be emptied by a parse that finds nothing**

Syncing a note that produced no cards used to delete the cards that deck already had. That is correct when someone has genuinely removed every card from a note. It is wrong in every other case — a header level that no longer matches the profile, a format the parser stopped recognising — and the result was the same either way: the deck emptied.

A sync that would empty a deck still holding cards is now refused. The note is left alone and the next sync tries again.

#### **What changed**

- A parse yielding zero cards no longer deletes an existing deck's cards.
- Callers that know an empty result is real — a canvas whose last edge was removed — can still allow it.
- Scheduling was never at risk here: card IDs come from the card's own text, and review history is restored from the review log when a card returns. This change is about the cards themselves.

If a deck of yours has shown 0 cards without the note changing, this is the release that stops it happening again. The cards return on the next sync once the mismatch is corrected.
